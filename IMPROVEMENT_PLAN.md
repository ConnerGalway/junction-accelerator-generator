# Dashboard Generator Improvement Plan

## Executive Summary

This document outlines the root causes of inconsistent dashboard generation and provides a prioritized action plan to achieve reliable, fully populated dashboards for all future clients.

---

## Part 1: Identified Issues

### 1.1 Missing Placeholder Handlers (Critical)

The `create-project.js` function is missing handlers for **35+ placeholders** that exist in the template. These fall into four categories:

#### Phase Placeholders (9 placeholders)
| Placeholder | Purpose | Status |
|-------------|---------|--------|
| `{{PHASE_1_WEEKS}}` | Week range (e.g., "WEEKS 1-4") | NOT HANDLED |
| `{{PHASE_1_NAME}}` | Phase name (e.g., "Foundation") | NOT HANDLED |
| `{{PHASE_1_DESC}}` | Phase description (1-4 words) | NOT HANDLED |
| `{{PHASE_2_WEEKS}}` | Week range for phase 2 | NOT HANDLED |
| `{{PHASE_2_NAME}}` | Phase 2 name | NOT HANDLED |

### 1.2 Parsing Logic Edge Cases (Medium Priority)

The plan.md parser has several fragile regex patterns that can fail:

1. **Objectives parsing**: Requires exact format `### Objective N\nTitle:\nDescription:\nTactic Pill:` - any deviation fails silently
2. **Tactic header parsing**: Requires exact format `## Tactic N: Title\nPhase:\nShort Label:\nSubtitle:` on consecutive lines
3. **Week parsing**: Requires exact format `### Week N: Title\n**Actions:**\n...\n**Checklist:**\n...`
4. **Part extraction**: Relies on `#### Part [A-Z]:` format - any variation fails

### 1.3 Validation Gaps (Medium Priority)

1. **No post-processing validation**: The function never checks if any `{{PLACEHOLDER}}` tokens remain in the output
2. **Silent failures**: When a regex doesn't match, it silently produces empty content
3. **No format validation**: The plan.md is not validated against expected schema before processing
4. **No error reporting**: Specific placeholder failures are not logged or reported

### 1.4 Architectural Issues (Design Debt)

1. **Assessment vs Plan separation**: Assessment data is generated by `generate-assessment-background.js` but plan dashboards expect it. Currently, `create-project.js` just empties all assessment placeholders with placeholder text.
2. **No regeneration mechanism**: When assessment data becomes available later, there's no way to update the dashboard.
3. **Template drift**: Template updates don't automatically propagate to existing client dashboards.

## Part 2: Root Cause Analysis

### Why did sasquatch-inn and harrison-beach-hotel fail?

Both dashboards show identical unfilled placeholders because:

1. **Phase placeholders were never added to `create-project.js`** when the template was updated to include them
2. **Week 1 dashboard placeholders were never implemented** - the "Your Next Step" card was added to template but no handler exists
3. **Assessment category scores require assessment data** which comes from a different generation pipeline
4. **JavaScript configuration placeholders were added to template** but never implemented in the processor

### Why were these issues not caught earlier?

1. **No automated testing**: No tests verify placeholder coverage
2. **No visual review step**: Generated dashboards aren't automatically opened for review
3. **No validation step**: No check that all placeholders were replaced
4. **Manual template updates**: Template changes aren't tracked against handler changes

## Part 3: Prioritized Fix Plan

### Priority 1: Add Missing Handlers (Immediate)

#### 1A. Add Phase Placeholder Handlers

Add to `processTemplate()` after the tactics loop:

```javascript
// Phase placeholders - derive from tactic phases or use defaults
const phases = [
  { name: data.tactics[0]?.phase || 'Foundation', weeks: 'WEEKS 1-4', desc: 'Build the base' },
  { name: data.tactics[1]?.phase || 'Growth', weeks: 'WEEKS 5-8', desc: 'Scale what works' },
  { name: data.tactics[2]?.phase || 'Optimization', weeks: 'WEEKS 9-12', desc: 'Refine and sustain' }
];

for (let i = 0; i < 3; i++) {
  const n = i + 1;
  html = html.split(`{{PHASE_${n}_WEEKS}}`).join(phases[i].weeks);
  html = html.split(`{{PHASE_${n}_NAME}}`).join(phases[i].name);
  html = html.split(`{{PHASE_${n}_DESC}}`).join(phases[i].desc);
}
```

// Week 1 "Your Next Step" card

### Priority 3: Add Plan.md Format Validation (This Week)

Add validation in `parsePlanMd()`:

```javascript
function parsePlanMd(content) {
  const errors = [];

  // Validate required sections exist
  if (!content.includes('## Goal')) errors.push('Missing "## Goal" section');
  if (!content.includes('## Tactic 1:')) errors.push('Missing "## Tactic 1:" section');
  if (!content.includes('### Week 1:')) errors.push('Missing "### Week 1:" section');

  // Validate format patterns
  const tacticCount = (content.match(/## Tactic \d+:/g) || []).length;
  if (tacticCount < 3) errors.push(`Found ${tacticCount} tactics, expected at least 3`);

  const weekCount = (content.match(/### Week \d+:/g) || []).length;
  if (weekCount < 12) errors.push(`Found ${weekCount} weeks, expected 12`);

  if (errors.length > 0) {
    return { error: errors.join('; ') };
  }

  // Continue with parsing...
}
```

### Priority 4: Improve Regex Robustness (Next Sprint)

Make regex patterns more forgiving:

```javascript
// Before (strict)
const headerMatch = section.match(/## Tactic (\d+):\s*(.+)\nPhase:\s*(.+)\nShort Label:\s*(.+)\nSubtitle:\s*(.+)/);

// After (more forgiving)
const headerMatch = section.match(/## Tactic (\d+):\s*(.+?)[\r\n]+Phase:\s*(.+?)[\r\n]+Short Label:\s*(.+?)[\r\n]+Subtitle:\s*(.+)/);
```

## Part 5: Long-term Architecture Improvements

### 5.1 Template-Handler Sync System

Maintain a manifest file that maps template placeholders to their handlers:

```json
{
  "placeholders": {
    "{{CLIENT_NAME}}": { "handler": "simple", "source": "data.clientName" },
    "{{PHASE_1_NAME}}": { "handler": "phase", "derived": true },
    "{{CATEGORY_1_SCORE}}": { "handler": "assessment", "requires": "assessment_data" }
  }
}
```

Use this to:
1. Generate validation tests automatically
2. Warn when template has placeholders without handlers
3. Document placeholder sources

### 5.2 Assessment Integration

Create a unified generation flow:

1. Generate assessment first (via `generate-assessment-background.js`)
2. Store assessment data in Supabase
3. Generate plan dashboard (via `create-project.js`)
4. Pull assessment data from Supabase to fill assessment placeholders
5. Or: Create separate "update dashboard with assessment" endpoint

### 5.3 Dashboard Regeneration Endpoint

Add endpoint to regenerate a client's dashboard:

```javascript
// POST /api/regenerate-dashboard
// Body: { slug: 'client-slug' }
// Pulls latest plan.md and assessment data, regenerates index.html
```
